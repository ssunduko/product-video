### Elements

| Element | Kind | Technology | Description |
|---|---|---|---|
| **Demo author** | Person | — | Developer or PM. Writes the flow in plain English or as a .demo script, points it at a deployment with a target, and builds the video: one stage at a time from a shell, or every part of a video with one build command. Nothing is delivered until it passes the quality gate and the video-qa review. |
| **Demo Video Pipeline** | Software System | `Node.js CLI stages` | Turns a plain-English flow into a narrated, branded MP4. Drives a real browser, captures frames and input telemetry, then assembles, zooms, composites, narrates, tightens and cards the result. The stages run one at a time by hand, or all of them per video through the build orchestrator; every video is measured by the quality gate before it is called done. |
| **Viewer** | Person | — | Prospect, customer or internal audience. Watches the finished MP4; never touches the pipeline. |
| **Google Chrome** | External System | `Chrome + DevTools Protocol` | Driven by puppeteer-core on a dedicated user-data profile — one per target, so a login survives between takes and a video can show two signed-in users without anyone signing in on camera. Frames come from Page.startScreencast. The cursor in the finished video is synthesized from telemetry rather than recorded, so the capture needs no real cursor. |
| **Web application under demo** | External System | `Any web app` | The deployment being recorded — localhost, staging, a customer sandbox, or a third-party app such as claude.ai. Named by a target; may require signing in. Flows run against live data, so the pipeline hovers rather than clicking anything destructive. |
| **ffmpeg / ffprobe** | External System | `Local CLI` | On PATH, or via FFMPEG / FFPROBE. Every encode, decode, probe and audio filter graph. The compositor also pipes raw RGBA through it in both directions, so no intermediate frame hits disk. |
| **Text-to-speech API** | External System | `ElevenLabs or OpenAI` | Chosen by DEMO_TTS, or by whichever key is set. Anthropic has no TTS API, so this is a third party. Keys come from the shell or .env, never a committed file. With Zep, the only network dependencies other than the app under demo. |
| **Claude in Chrome extension** | External System | `Browser extension` | Drives the user own Chrome, with their own session, so there is no SSO ritual and no email code to fill. Used before a take to turn the natural-language ask selectors in a script into concrete ones against the live DOM. It cannot record: it has screenshot capture but no screencast, so the take itself stays with the CDP driver. |
| **video-qa agent** | External System | `Claude Code subagent` | Reviews a finished video: runs the quality gate, then checks every narration line against a still of the screen — is the thing being described on screen while it is said? — and returns PASS or FAIL with the fix for each defect. Read-only. Defined in .claude/agents/video-qa.md. |
| **memory agent** | External System | `Claude Code subagent` | Runs at session start when a feature source is stale: lists each online source of an app with its MCP tool, reads what changed, merges its features into the catalog and pushes them to Zep. Read-only on the sources. Defined in .claude/agents/memory.md. |
| **Online feature sources** | External System | `e.g. a Google Drive folder per app` | Where the features of each app are published, located by FEATURE_SOURCE_{APP} in .env. Reachable only as Claude tools (MCP), so the memory agent reads them, never the pipeline. |
| **Zep Cloud** | External System | `@getzep/zep-cloud · HTTPS` | Searchable memory: one graph per app for feature pages, traces and manifests, one for rules and pipeline notes, and a thread per working session. Key in ZEP_API_KEY (.env). |
| **Video destination** | External System | `Google Drive API v3 · HTTPS` | Where finished videos are published: a Google Drive folder per app, located by PUBLISH_DEST_{APP} in .env. Uploads run as the signed-in user (OAuth refresh token in .env). |
| **Jira** | External System | `Atlassian MCP` | The ticket each video is for (the manifest names it). Claude posts the published link there as a comment through the Atlassian MCP tool; the pipeline only records that it was posted. |

### Elements

| Element | Kind | Technology | Description |
|---|---|---|---|
| **Demo author** | Person | — | Developer or PM. Writes the flow in plain English or as a .demo script, points it at a deployment with a target, and builds the video: one stage at a time from a shell, or every part of a video with one build command. Nothing is delivered until it passes the quality gate and the video-qa review. |
| **Google Chrome** | External System | `Chrome + DevTools Protocol` | Driven by puppeteer-core on a dedicated user-data profile — one per target, so a login survives between takes and a video can show two signed-in users without anyone signing in on camera. Frames come from Page.startScreencast. The cursor in the finished video is synthesized from telemetry rather than recorded, so the capture needs no real cursor. |
| **Web application under demo** | External System | `Any web app` | The deployment being recorded — localhost, staging, a customer sandbox, or a third-party app such as claude.ai. Named by a target; may require signing in. Flows run against live data, so the pipeline hovers rather than clicking anything destructive. |
| **0 · Author** | Container | `author.mjs · Node.js` | Turns an observed walk of the app into the DSL. Reads a trace — the selectors found and the wait times measured — and emits the .demo and its selector sidecar together. Sizes the narration to each measured wait, reports any line that will not fit, and proposes a SPEEDS_MS range for whatever narration cannot cover. With --check it re-authors every trace in memory and fails while a committed script differs (pre-commit and CI). Optional: a .demo can be written by hand. |
| **Observed traces** | File store | `scenarios/*.trace.json` | What the app actually did on a real walk: the selector each step needs, the evidence for it, and how long every wait took. Authored, not generated — it is the only artifact here that cannot be rebuilt from something else, which is why it lives in scenarios/ rather than the gitignored out/. Also carries hazards the DSL cannot yet express, which the author writes into the script header. |
| **1 · Script Compiler** | Container | `script.mjs · Node.js` | Compiles a .demo flow into a normal, inspectable scenario module. Refuses to clobber a hand-written scenario. driver.mjs also calls it on the way in. |
| **2 · Driver** | Container | `driver.mjs · Node.js + puppeteer-core` | Launches Chrome, signs in if the target says to, runs the flow, and records a screencast plus cursor, click and narration-cue telemetry, plus the real start and end of every wait. Per target it records from its own Chrome profile, keeps chat widgets from loading and hides app banners. Closes Chrome cleanly so cookies flush. |
| **3 · Assembler** | Container | `assemble.mjs · Node.js + ffmpeg` | Turns frames into raw.mp4 / cut.mp4. Applies CUTS_MS (drop) and SPEEDS_MS (keep, play fast) and puts the cursor and narration telemetry through the same shift, so nothing desyncs. With AUTO_SPEED it fast-forwards every logged wait nobody is talking over. Prints the largest inter-frame gaps. |
| **4 · Zoom Projector** | Container | `project.mjs · Node.js` | Clusters clicks less than 2.5s apart into zoom regions, each carrying a focusTrack the compositor pans across, and writes {take}.recordly. |
| **5 · Compositor** | Container | `compose.mjs · Node.js + canvas + ffmpeg` | Renders every frame: eased zoom/pan, a synthesized cursor with click ripples, and a styled window frame. Frames stream through ffmpeg both ways; nothing hits disk. |
| **6 · Narrator** | Container | `narrate.mjs · Node.js + ffmpeg` | Voices the say-cues, trims the breath off each clip, levels every clip to a common loudness, and mixes them onto the video. Extends the video by holding the last frame if a closing line overruns it. |
| **7 · Tightener** | Container | `tighten.mjs · Node.js + ffmpeg` | Compresses stretches that are frozen AND silent, trims the trailing run, and crossfades every seam. Runs after narrate because silence is only meaningful once the voice is on the timeline. Refuses to write if a seam lands on speech or a zoom. Always writes its output, even with nothing to cut, so the next stage can never pick up an earlier take. |
| **8 · Card Renderer** | Container | `cards.mjs · Node.js + canvas + ffmpeg` | Renders branded intro/outro title cards, voices them with the same provider, and dissolves them on with the concat filter rather than the demuxer. |
| **Flow definitions** | File store | `input/ + scenarios/ authored, scripts/ generated` | What happens on screen and what is said over it. Split by who writes it: input/ holds the plain-English .flow and scenarios/ the .trace.json observed from walking it, both authored and worth reviewing; scripts/ holds the .demo the trace generates, plus its selector sidecar, either of which can be deleted and rebuilt. Committed; contains no credentials. |
| **Targets & secrets** | File store | `targets/*.json, *.local.json, .env` | Which deployment, and how to sign in. The .json is committed and holds no secrets; the .local.json and .env are gitignored. Any value may be written env:VAR_NAME and is read from the environment at load time. A target can also name its own Chrome profile, URLs to block, selectors to hide, and secrets that fill {name} placeholders in an open path. |
| **Brand assets** | File store | `brand/` | StyleGuide.txt (colour and type, the source of truth), the logo, and the font files. One directory is the brand; there is no flag to point elsewhere. |
| **Work directory** | File store | `out/ · out/{video}/{part}/` | One folder per take: out/ by default, or out/{video}/{part}/ when the build orchestrator sets DEMO_OUT, so takes never overwrite each other. Holds frames/, frames.json, actions.json, the per-take cursor.json and narration.json, {take}.recordly, the MP4 at each stage (raw, cut, final, final-narrated, -tight, -carded) and the quality gate report with its stills. The hand-off between every stage. |
| **TTS clip cache** | File store | `out/tts/ · mp3` | One mp3 per line, keyed by provider+voice+text, plus the derived .lead.mp3 with the opening breath trimmed. Re-cutting or re-composing re-bills nothing; only changed lines re-render. Shared by every take folder. |
| **Selector resolutions** | File store | `scripts/*.selectors.json` | What each ask description resolved to against the live DOM, plus the evidence for it. Kept beside the script rather than inside it, so the .demo keeps saying what you meant while the machine-found selector stays reviewable on its own. Keyed by intent text, so renaming a selector or reordering the block does not orphan a resolution. |
| **Claude in Chrome extension** | External System | `Browser extension` | Drives the user own Chrome, with their own session, so there is no SSO ritual and no email code to fill. Used before a take to turn the natural-language ask selectors in a script into concrete ones against the live DOM. It cannot record: it has screenshot capture but no screencast, so the take itself stays with the CDP driver. |
| **ffmpeg / ffprobe** | External System | `Local CLI` | On PATH, or via FFMPEG / FFPROBE. Every encode, decode, probe and audio filter graph. The compositor also pipes raw RGBA through it in both directions, so no intermediate frame hits disk. |
| **Text-to-speech API** | External System | `ElevenLabs or OpenAI` | Chosen by DEMO_TTS, or by whichever key is set. Anthropic has no TTS API, so this is a third party. Keys come from the shell or .env, never a committed file. With Zep, the only network dependencies other than the app under demo. |
| **9 · Quality Gate** | Container | `qa.mjs · Node.js + ffmpeg` | Measures what a viewer notices and a stage only warns about: two narration lines at once, a line off its cue, dead air, a frozen or loading screen, black frames, mismatched streams, loudness, and a deliverable built from a previous take. Writes a report and a still per line and per flagged range, and exits 1 on any failure. |
| **Build Orchestrator** | Container | `build.mjs · Node.js + ffmpeg` | Builds a whole video from its manifest: records and renders every part into its own folder, gates each on the quality gate, trims the silence at each join by measurement, crossfades the parts and gates the result. Stops at the first failed gate. |
| **Video manifests** | File store | `videos/*.json` | One per finished video: its parts in recording order with what must be true before each take, the settings every stage runs with, and how the parts join. Committed. |
| **Browser profiles** | File store | `profile/, profile-*/ · gitignored` | Chrome user-data directories holding signed-in sessions, one per target that needs its own user. Signed in by hand once; a take never signs out. Sensitive: whoever has the folder has the session. |
| **video-qa agent** | External System | `Claude Code subagent` | Reviews a finished video: runs the quality gate, then checks every narration line against a still of the screen — is the thing being described on screen while it is said? — and returns PASS or FAIL with the fix for each defect. Read-only. Defined in .claude/agents/video-qa.md. |
| **Memory** | Container | `memory.mjs · Node.js + @getzep/zep-cloud` | Bookkeeping for project memory: finds the source of each app from .env, diffs a remote listing against the sync lock next to the catalog (files older than the catalog are its baseline), merges new features into the catalog, reports stale sources (SessionStart hook and build.mjs), and pushes changed catalog features, pages, traces and manifests to Zep. |
| **Project memory** | File store | `memory/ · committed` | rules.md (imported by CLAUDE.md), features/{app}/data/features.json (the feature catalog, the initial set), features/{app}/*.md (one page per filmed feature, naming its videos), sources.json (generic: kinds of source; locations are in .env). A private app folder is gitignored. |

### Elements

| Element | Kind | Technology | Description |
|---|---|---|---|
| **Demo author** | Person | — | Developer or PM. Writes the flow in plain English or as a .demo script, points it at a deployment with a target, and builds the video: one stage at a time from a shell, or every part of a video with one build command. Nothing is delivered until it passes the quality gate and the video-qa review. |
| **Publish plan** | Component | `check` | The file, its destination (PUBLISH_DEST_{APP} and its kind), the ticket from the manifest, and every reason it may not be published yet: state not done, file missing, destination or Google credentials not set. |

| **Approval gate** | Component | `upload --approved` | Refuses unless the video state is done (or already published) and --approved is given, which Claude passes only after the user says to publish. |
| **Drive uploader** | Component | `resumable upload · 8 MB chunks` | Uploads into the destination folder as the user, or adds a new revision of the file published before so its link stays the same. |
| **Publication record** | Component | `memory.mjs recordVideo · video sync` | Records the link, file id and destination in the video state (status published), posts it to the video thread and states it as facts in the app graph. jira records the comment Claude posted. |

| **Video destination** | External System | `Google Drive API v3 · HTTPS` | Where finished videos are published: a Google Drive folder per app, located by PUBLISH_DEST_{APP} in .env. Uploads run as the signed-in user (OAuth refresh token in .env). |
